# tile-takeoff — حصر البلاط من المخطط

**كميات محسوبة من المخطط، لا مُخمَّنة.**

[English](README.md) · رخصة MIT · بايثون ‎3.10+‎

كل مشروع تبليط يبدأ بالسؤال نفسه: كم متراً مربعاً نحتاج؟ ولأن أحداً لا يحسبها بدقة،
العادة المتّبعة في القطاع هي إضافة نسبة هدر جزافية — بين ١٠٪ و٢٠٪ فوق المساحة الصافية.
هذا الرقم ليس تقديراً، بل تأميناً ضد الجهل بكيفية تقطيع البلاط.

والنتيجة شيئان في الحاوية: مال دُفع على بضاعة لم تُفرش، والبضاعة نفسها — والسيراميك
المكسور من أصعب مخلفات البناء إعادةً للتدوير، فينتهي في الردم.

هذه الأداة تستبدل بالتخمين حساباً. تعطيها مخطط PDF ومقاس اللوح أو البلاطة، فتعيد لك
مخطط التقطيع، ونسبة الهدر الحقيقية، والكمية الواجب طلبها.

```
SLAB  295 × 175 cm   (5.1625 m²)

RECOMMENDED   147.5 × 87.5 cm
  2×2 cut · 4 tiles per slab · 0.0% waste · 1.291 m² per tile

OFF-THE-SHELF SIZES (for comparison)
          tile cm  per slab     waste
            60×60         8     44.2%
            80×80         6     25.6%

QUANTITIES   floor = 98.00 m²
  tiles needed            : 76
  slabs, +10% allowance   : 21
```

تقطيع اللوح نفسه إلى بلاط ٦٠×٦٠ يرمي ٤٤٪ منه. الأداة لا تقرر عنك — تُريك ثمن كل خيار.

## التثبيت

```bash
pip install "tile-takeoff[all]"
```

`[all]` تجلب PyMuPDF لقراءة الـPDF وmatplotlib لرسم مخطط التقطيع. أما حسابات التقطيع
نفسها فبلا أي اعتماديات — يكفيك `pip install tile-takeoff` إن كانت مساحاتك معروفة سلفاً.

## الاستعمال

**افحص المخطط أولاً** — كم لوحة، وبأي مقاس، وهل تحمل الصفحة طبقة نص حقيقية (مُصدَّرة من
أوتوكاد) أم أنها صورة ممسوحة تُقرأ بصرياً فقط:

```bash
tile-takeoff survey plan.pdf
```

**صيّر الصفحات** لتصير مقروءة فعلاً. نصوص الأبعاد صغيرة، وقصّةٌ بدقة ٣٥٠ نقطة تتفوّق على
الصفحة كاملة بدقة ١٥٠ في كل مرة:

```bash
tile-takeoff render plan.pdf --out ./pages --pages 1,3 --dpi 150
tile-takeoff render plan.pdf --out ./pages --pages 2 --dpi 350 --crop 0.5,0,1,0.5
tile-takeoff render plan.pdf --out ./pages --pages 2 --dpi 300 --grid 2x3
```

`--crop` تأخذ نِسباً من الصفحة (`x0,y0,x1,y1` كلٌّ بين ٠ و١). و`--grid` تمسح اللوحة
المزدحمة (A0/A1) على هيئة مربعات متداخلة، فيبقى البُعد الواقع على حدٍّ فاصل ظاهراً
كاملاً في أحدها.

**استخرج طبقة النص**، فهي تؤكد ما قرأته بصرياً وتلتقط ما فاتك:

```bash
tile-takeoff text plan.pdf --pages 1-4
```

**احسب التقطيع والكميات:**

```bash
tile-takeoff optimize --slab 295x175
tile-takeoff optimize --slab 295x175 --area 98
tile-takeoff optimize --slab 295x175 --floor 1050x810 --area 98 --draw layout.png
```

| الخيار | المعنى |
|---|---|
| `--slab` | مقاس اللوح الخام بالسنتيمتر، مثل `295x175` |
| `--area` | مساحة الأرضية بالمتر المربع |
| `--floor` | مقاس الغرفة بالسنتيمتر، ليختار البرنامج الاتجاه الأقل حاشيةً |
| `--max-side` | أطول ضلع عملي للبلاطة، افتراضياً ١٥٠ سم — فوقها يصعب الحمل ويرتفع خطر الكسر |
| `--min-side` | أقصر ضلع يستحق النظر، افتراضياً ٤٠ سم |
| `--allowance` | احتياطي الكسر والقص في الموقع، افتراضياً `0.10` |
| `--draw` | حفظ رسم مخطط التقطيع في ملف PNG |

## كمكتبة برمجية

```python
from tile_takeoff.cutting import recommend, fit_to_floor, Takeoff

best = recommend(295, 175, floor_width_cm=1050, floor_height_cm=810)
print(best.width_cm, best.height_cm, best.per_slab)     # 147.5 87.5 4

quantities = Takeoff(area_m2=98, tile_area_m2=best.area_m2, slab_area_m2=5.1625)
print(quantities.slabs_with_allowance)                   # 21
```

## في المتصفح

مجلد `web/` صفحة ساكنة تنجز العمل كاملاً بلا خادم: تفتح الـPDF بنسخة مرفقة من pdf.js،
وتشغّل حسابات التقطيع نفسها مكتوبةً بجافاسكربت، وترسم مخطط القص على canvas.
**المخطط لا يغادر الجهاز** — إذ لا توجد أصلاً وجهة رفع يُرسل إليها، والصفحة تعمل بلا
إنترنت بعد أول تحميل.

مباشرة على **https://hanysyria.github.io/tile-takeoff/**، أو شغّلها محلياً:

```bash
python -m http.server 8777 --directory web
```

الملف `web/cutting.js` مرآةٌ لـ`src/tile_takeoff/cutting.py`، والملف `web/cutting.test.mjs`
يثبّت الحالة المرجعية نفسها باللغتين — فإن اختلفت النسختان يوماً على كمية، سقط الـCI.

```bash
node --test web/cutting.test.mjs
```

## ما لن تفعله الأداة

**لن تخمّن بُعداً أبداً.** المخطط الخالي من الأبعاد المدوّنة وبلا مقياس مقروء ينتج عنه
طلبُ معلومات، لا حصرُ كميات. هناك من سيدفع مالاً بناءً على هذا الرقم.

**لن تثق بمقياس الرسم المطبوع وحده.** التصدير والطباعة يغيّران حجم الصفحة دون تحديث
عبارة «1:50» المكتوبة عليها. وللقياس من صورة: عايِر نسبة البكسل إلى المتر مقابل بُعدٍ
**مدوَّن** في الصورة نفسها، ثم تحقّق من المعايرة ببُعد مدوَّن ثانٍ قبل الاعتماد عليها.

**انتبه للوحدات.** المخططات المعمارية غالباً بالمليمتر — `3600` تعني ٣٫٦٠ م — لكن ليس
دائماً. استنتج الوحدة من السياق (سماكة الجدار ٢٠٠–٣٠٠ مم) وصرّح بما استنتجته.

**صرّح بمصدر كل رقم.** مقروء من المخطط، أو مقيس بالمعايرة، أو مفترض — ثلاث درجات ثقة
مختلفة، ولا يجوز للناتج أن يخلط بينها.

## نسب الهدر

القيم الافتراضية أعراف مهنية لا قوانين فيزياء:

- ١٠٪ للفرش المستقيم
- ١٥٪ للفرش الدياغونالي، أو الغرف كثيرة الزوايا، أو البلاطات كبيرة المقاس (٦٠×١٢٠ فما
  فوق) لكثرة القص فيها
- الحجر الطبيعي هدره أعلى قليلاً من البورسلان — ارفع النسبة عند الشك

وحين يُحسب التقطيع فعلاً، تصير النسبة تغطيةً للكسر وخطأ الموقع بدل أن تكون تغطيةً
للجهل — ولهذا يمكن أن تنخفض.

## التطوير

```bash
git clone https://github.com/hanysyria/tile-takeoff.git && cd tile-takeoff
pip install -e ".[dev]"
pytest
python examples/make_example_plan.py   # لإعادة توليد المخطط الاصطناعي للاختبار
```

الملف `examples/example_plan.pdf` يولّده المستودع بنفسه: لوحة اصطناعية صغيرة بأربع غرف
وأبعاد مدوّنة. لا توجد فيه أي مخططات مشاريع حقيقية، ولا ينبغي أن توجد — فمخطط البيت
بيانات خاصة بأصحابه.
