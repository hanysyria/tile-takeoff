# Contributing

Thanks for looking. This is a small tool with one job: replace a guessed waste allowance
with a computed one.

## Getting set up

```bash
pip install -e ".[dev]"
pytest
```

`examples/example_plan.pdf` is generated by `examples/make_example_plan.py`. Regenerate it
rather than editing it by hand.

## Never commit a real drawing

A floor plan is somebody's home. Test fixtures must be synthetic — extend
`make_example_plan.py` if you need a drawing with different characteristics (a scanned
sheet, imperial units, a rotated title block). Pull requests carrying a real project
drawing will be asked to remove it, whatever the licence on it.

## What's especially useful

- **Drawings the reader mishandles.** Unusual units, unusual conventions, a scale block it
  can't verify. Describe the drawing and what went wrong — you don't need to attach it.
- **Lay patterns not yet modelled.** Herringbone, hexagons, borders and inlays, mixed tile
  sizes in one room. The cutting maths currently assumes a rectangular grid.
- **Translations.** The README exists in English and Arabic; more are welcome, and so are
  corrections to the Arabic.
- **Waste conventions from other markets.** The default allowances are the ones common in
  Gulf residential work. If your market's norms differ and you can say why, that's worth
  documenting.

## Code

- Python 3.10+, standard library where possible. PyMuPDF and matplotlib stay optional
  extras — the cutting maths must keep working with neither installed.
- Add a test for anything that changes a number. The tests in `tests/test_cutting.py`
  check properties (waste is never negative, rounding never goes down, an allowance never
  reduces an order) rather than just golden values; prefer that style.
- Comments explain why, not what.

## Reporting a wrong number

Include the slab size, the room size or area, the flags you passed, what the tool said,
and what you expected. A wrong quantity is the most serious kind of bug this project can
have — it will be treated that way.
